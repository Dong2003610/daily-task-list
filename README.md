# 每日任务清单 · v2

一个轻量的每日工作清单。支持任务管理、历史搜索、跨日接续、专注计时、提醒、重复任务和备份导出。

线上地址：https://dong2003610.github.io/daily-task-list/

## 日常使用

- 在首页输入任务，按回车快速添加；“详细添加”可设置优先级和提醒。
- 新的一天首次打开时，提示勾选昨天未完成任务。“今天不再提示”随账号保存；也可从“未完成任务等待继续”查看更早遗留任务。
- 迁移创建今天的副本，原历史保留。名称与优先级保留，计时归零，过期提醒清除、未来提醒保留。同名独立任务不会被合并。
- 删除有 8 秒撤销期；过期后才发起删除。失败会保留待处理记录并提供“重试删除”，刷新可继续处理。
- 手机上任务列表在前，计时器默认折叠。开始计时后，小计时栏固定在屏幕底部，可展开、暂停和停止。
- “历史任务”可以同时按名称、日期、完成状态筛选，按日期倒序展示。
- “重复任务”支持每天、工作日（周一至周五）、每周指定日期，并可设置提醒、暂停、编辑、删除。打开或返回网站及跨日时生成当天任务，不补建未打开网站那些天的任务。
- “导出备份”导出全部任务：CSV 适合表格软件；JSON 还包含重复规则和相关设置。不会导出登录 Token。
- 提醒会在打开页面、恢复焦点、电脑休眠后补查到期任务，并在本设备记住已确认的提醒。关闭网站时不能发送提醒；声音需浏览器允许播放。
- 日期归属与重复规则统一按北京时间（Asia/Shanghai，UTC+8），避免跨时区设备产生不同的“今天”。

## 源码与部署

GitHub 仓库根目录仍作为 Pages 网站，维护源码位于 `app/`。旧资产保留用于回退，不要把旧压缩文件当作维护入口。

需要 Node.js 22+ 与 npm。在仓库的 `app/` 目录内运行；本地独立源码副本直接在其根目录运行：

```powershell
npm ci
npm run dev
npm test
npm run test:e2e
npm run build
node scripts/publish.mjs --dry-run
```

浏览器测试默认使用本机 Edge；可以通过 `EDGE_EXECUTABLE` 指定可用 Chromium/Edge 可执行文件。测试会隔离并模拟账号和后端，不访问真实任务数据。

构建产物在 `dist/`。`scripts/publish.mjs` 通过 GitHub REST API 一次提交构建产物、源码和测试，适用于 git push 受限制的网络。它仅发布白名单目录、保留线上无关文件，并检查 main 在发布期间没有变化。

授权仅在本机临时设置 `GITHUB_TOKEN` 后执行 `node scripts/publish.mjs`，或执行 `node scripts/publish.mjs --token-stdin` 进行隐藏输入。Token 仅需该仓库 Contents 读写权限。不要把 Token 写入源码、`.env`、提交或聊天。

客户端使用个人 Supabase 项目的公共配置和会话存储。仍使用原用户名登录（内部映射为 `用户名@miaoda.com`），不会自动创建匿名身份。数据库初始化脚本位于 `supabase/schema.sql`；可通过 `.env.local` 覆盖公共项目配置，禁止放入 service-role key。

## 数据与一致性

任务继续使用现有 `tasks` 表及账号 RLS，没有改名、迁移或覆盖原任务。迁移和重复实例使用确定性的 UUID、数据库主键与 insert-on-conflict-do-nothing；重试不会覆盖已编辑或已完成的同一实例。

重复规则、当天提示状态和取消标记存放在当前账号的 `user_metadata` 独立命名空间。规则上限 20 条，应用设置总容量限制 6 KB，防止认证请求头膨胀；大量规则/长期大规模记录应升级为独立设置和实例表。并行修改同一条规则采用最后保存结果，不提供版本合并。

旧版本通过随机 ID 复制的同名任务没有来源关联，无法可靠自动判重，所以较早的遗留任务需要用户自行勾选。新版本能识别自己的确定性迁移链，避免再次接续已迁移或已完成的祖先任务。

计时保存采用串行请求及数据库单调条件，避免旧设备把累计时长写小；同时在两台设备计同一任务不保证时长相加。计时进度和删除撤销状态会作本机备份，浏览器存储不可用时不能保证刷新恢复。

详情与验收记录见 `tests/README.md` 和 `docs/RELEASE.md`。JSON 备份供恢复工具使用，当前界面不提供一键导入。

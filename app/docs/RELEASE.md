## 验证

- `npm run build`：TypeScript 检查与生产构建。
- `npm test`：日期边界、迁移关联与确定性 ID、重复计划、提醒补漏、CSV 公式转义、API 账号隔离。
- `npm run test:e2e`：隔离浏览器中的添加/失败重试、迁移与重放、撤销删除、重复规则生成、搜索、分页、提醒确认、跨日、手机布局与导出。
- 截图位于本地 `test-results/`，不随源码发布。
- 浏览器自动化使用模拟账号/数据库，不对真实任务进行试写。真实环境的账号权限或网络差异仍可能在首次使用时表现为同步错误；此时保留草稿并展示重试信息。

## 发布

1. 完成构建和全部测试。
2. 执行 `node scripts/publish.mjs --dry-run` 审核文件名单。
3. 使用已授权的仓库 Contents 读写凭据执行发布；可用 `EXPECTED_HEAD` 锁定预期线上提交。
4. 确认新 GitHub Pages 页面引用新的 hash 资产，并核对线上 JS/CSS 与 `dist/` 字节一致。

## 回退

发布脚本不删除旧 hash 资产。需要回退时，可从上面的基线提交恢复根 `index.html` 和 `404.html`，即可重新加载旧界面；建议以新提交回退，不强推分支。新增任务与原任务共用原数据表，仍可从旧版本查看；新重复规则保留在账号设置中，旧界面不会处理它们。

跨设备取消和插入发生在不同后端请求中，客户端通过取消标记、插入后复核和刷新过滤收敛。它们不是跨表数据库事务；严格的服务端调度/审计/无限历史规模需要额外后端表与迁移授权。

## 2026-10-21 长期开页同步优化

- 每日任务和当前周计划自动检查改为分页 ID/更新时间清单；只拉取变化详情，清单同时用于对齐其他设备的硬删除。详情按 100 个 ID 分批，失败不应用半份快照。
- 活跃约 60 秒检查，空闲两分钟后约 300 秒；隐藏或离线暂停，恢复时补查并合并 30 秒内的重复唤醒，失败指数退避至 300 秒。重复规则等账号设置自动读取间隔至少五分钟。
- 初次打开、切周和手动刷新保留完整读取；写操作立即保存。拖动排序直接合并服务器响应，不再成功后重下全部历史。计时的 15 秒保存保持不变。
- 隐藏跨日时延后当天重复任务生成，返回页面补建，不影响已经运行的计时。
- 复用现有 `updated_at` 触发器，无新增 SQL 或数据迁移。清单流量仍随任务数量增长，不承诺固定比例的实际账单下降。
